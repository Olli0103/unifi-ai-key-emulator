# Saved caption camera additions — 31 October 2026

Bounded software work for issues #13 and #17; their broad scopes remain OPEN.
This is not initial continuous-caption provisioning, model-family expansion,
native adoption, live scope activation or a claim that a backend is healthy.

## Existing boundaries reused

The existing configuration store, own pinned inventory reader, authentication,
CSRF/Origin and shared admission, opaque choice grants, bounded expiry and
shielded/drained file operations already provide the needed primitives. No
new dependency or service is introduced. The remove-only operation remains
remove-only; additions have separate typed methods and routes.

An existing explicit native camera list with room below sixteen is required.
Only freshly connected smart-event candidates from already allowed model
families are offered. Missing/model-wide policies are not converted. The
inventory Protect version must equal the saved version. Duplicate IDs/MACs
refuse the report; ambiguous or identifier-like names are not offered. This
metadata classification does not prove native event delivery or model quality.

The store appends distinct additions in deterministic order, preserves existing
order, and changes only `worker.continuous.camera_ids`. It uses the existing
lock, exact old-byte private history, optimistic revision and immutable
identity/search/credential-route guards. Every other raw field, including
omitted defaults and cost mode, is preserved. No budget file is read, reset,
refunded or rewritten, and no provider Undo is created. Lost post-publication
acknowledgement is uncertain, never an automatic retry or claimed rollback.

Choices bind session/revision/native identity/MAC/name/model with structured
HMAC input. Preview and confirmation each re-read inventory; confirmations
recheck the exact result/revision, session and ten-minute monotonic expiry.
There are at most 32 live single-use grants, without evicting valid grants.
Names/model labels are escaped; the form/aggregate JSON do not expose native
camera IDs/MACs, protected paths, credentials or raw exceptions.

All consent boxes start unchecked. Camera processing/cost-policy consent and
save confirmation are distinct. With an existing local-unmetered policy, a
third separate acknowledgement explicitly accepts using that bypass for the
additional cameras; a local endpoint does not prove free inference. Metered
mode retains its existing shared reservation limit, which is not a total-bill
or price cap. No feature, native camera setting, model selection, cost mode,
in-flight authority or request policy is changed. A separately controlled Key
restart is still required; this form never starts one or invokes inference.

## Qualification boundary

39 new cases cover exact raw one-field append and full consumed-ledger byte
preservation, immutable history, stale/repeated selections, malformed fields,
missing/model-wide/full policies, explicit cost/bypass consent, expiry, fresh
name/model/MAC/ID/state/class/version/age changes, foreign sessions, concurrent
confirmation, logout during inventory, bounded grants, admitted-write
cancellation/drain and committed acknowledgement loss. Existing restriction,
cost-policy and store regressions also passed in a combined 125-case run before
the last two new cases were added; all 39 new cases subsequently passed.

Real sandboxed Chrome desktop/mobile/keyboard flows pass with fictional inputs,
zero foreign requests and no actual processor/provider/controller/media work.
Initial, review and saved decoded assets were inspected. A capture after native
form validation was vertically shifted; the retained reviewed capture is taken
on the initial unsubmitted review instead, with all consent boxes unchecked.
Validation refusal is still exercised twice before the actual confirmed save.
No product setting or guard was loosened for the screenshot. Browser temporary
profiles/servers are collected and all application-module hashes recorded.

These are same-agent fixture checks, not independent review, deployment,
physical camera activation, billing, persistence or model-quality evidence.
Frozen full tests, CI, package verification and native Admin qualification are
separate gates. No real household camera scope is changed by qualification.
