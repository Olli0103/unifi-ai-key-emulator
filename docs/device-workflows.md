# Complete private operator workflow

These typed pages manage saved settings without a JSON editor. They reuse the
configuration/runtime validators and the [private administration API](admin-api.md).
They do not replace Protect's native editor or a host operator's authority.

## Choose independent profiles

Use [Key browser preparation](first-run.md#authenticated-browser-preparation) or
[Port browser preparation](first-run-aiport.md) for a new private directory.
Never run first-run over an adopted profile. The normal `local-aikey-control run`
accepts a Key, a default Port, named Ports, or both kinds. Attach only actual
profiles: omit `--aikey-config` for Port-only administration. At least one is
required. Existing names, MACs, certificate/private-key bytes and unrelated
configuration are not regenerated by the following operations.

## Operator path and boundaries

| Page or operation | Supported workflow | Explicit boundary |
| --- | --- | --- |
| Overview, identities, active runtime, native status | Separate saved/adopted/connected/unknown observations, queue/errors and capabilities | Saved policy is not activation. Missing telemetry is unknown, not zero. |
| Devices | Review a new controller host, public PEM and independently verified SHA-256 for one profile; separately review Key search trust | Own device key/cert retained. No anonymous scan or automatic certificate acceptance. |
| Devices: test | One anonymous bounded TLS handshake per reviewed channel; normal CA validity plus exact peer pin | No client certificate/key, HTTP request, controller login or model call. No native adoption claim. |
| Camera pairing and capture | Guided native pairing/zone edits in Protect, then separately review local relay camera allowlist; initial object API provider setup if absent | Local capture is not native pairing. Fresh named eligible G3/G4/G5 inventory, at most five and existing capacity limits; no new face/plate/audio rights. |
| ONVIF references | Add/edit/remove named metadata with independent write-only username/password, camera host/port and explicit TLS pin; remove all even with damaged old credentials | Configuration only. Discovery, ingest, PTZ and recording are unsupported; no camera login or processing permission is created. |
| Local feature services (Key) | Initial/change/disable named recognition, enhancement and deep/ReID/optional rerank service addresses | Fixed existing model/vector contracts, no installation. Recognition selects named cameras; enhancement/deep process controller-requested jobs and have no local per-camera allowlist. |
| AI Port feature permissions | Initial/change/disable face, audio/speech presence and local sound permissions for named existing capture cameras; explicit installed model choice | Sound needs existing audio permission. No implicit parent permission or scope broadening. Fixed 512-value native face space, distinct from Key 128-value named identities. |
| Providers, models, plate OCR, caption and speech setup | Independent role/provider/model/route and write-only key replacement, catalog, explicit supported synthetic probes, preview/apply/Undo | Catalog is not quality. Unsupported role tests are labeled unavailable; no real camera input is invented to pass them. |
| Camera policy, processing/budgets, privacy/retention | Thresholds, per-feature/plate rights, cost policy and skip observations, retention and separate explicit deletion | No new object-event cap; no implicit cloud, audio, face or plate opt-in. Native zones remain controller-owned. |
| Search/indexes and maintenance | Index consequences and guarded migration; verified backup/restore/update plans and redacted diagnostics | Host-approved workers/receipts only. No arbitrary command/path, restart button or unsupported operation presented as successful. |

Native pairing/zone editing in Protect is a no-JSON graphical step, not an
unimplemented local write secretly treated as done. In particular, saving a
relay list does not prove a native pairing exists. Native grouping, OCR quality,
real alarms, physical ONVIF, real-client VPN layout and release readiness retain
their own original acceptance gates.

## Review, save and undo

1. Load the named profile and use its current form. Inventory failure is shown
   as unavailable, not an empty consent scope. Explicit disable-all remains
   available where no fresh grant is needed.
2. Review the exact controller pins, names, destination/model, changed fields,
   privacy/cost and feature consequences. Browser camera/model choices are
   opaque, session/revision-bound server declarations, never editable paths.
3. Check each initially unchecked acknowledgement, then confirm once. The
   server retains private candidate bytes and secrets; confirmation carries
   only the one-use token/profile/consents. It expires after ten monotonic
   minutes. Named inventory is re-observed before commit; stale, renamed,
   offline or reidentified cameras refuse the old decision.
4. Saved bytes are read back. Running services remain unchanged until a
   separately authorized activation. Logout/revocation prevents unadmitted
   work; an already admitted file operation is retained and drained.
5. Devices offers **Review prior saved settings** only for the current completed
   device transaction. Later unrelated writes disable that Undo. Normally it
   restores exact prior configuration bytes and retained resources.

**Port face exception:** first model binding establishes a private MAC-bound
vector-space guard. Undo restores the prior feature policy but retains that
guard. Disabling never resets it. Same-byte path relocation is allowed; changed
detector/encoder pins or preprocessing need separate migration. Generic patches
cannot bypass the established guard. This is not byte-exact restoration in the
initial-binding case, and the response identifies the exception explicitly.

Any possibly committed save is **uncertain**, not failed/rolled back. A private
durable intent fences configuration writers and runtime startup. Use the
explicit saved-byte reconciliation review: matching before/after bytes settle
the retained transaction without rewriting configuration, restarting, retrying
or discarding staged resources. Unknown/mismatched state stays blocked. Keep the
whole state directory mounted in the supported container recipe; the journal,
history, selected references and retained objects are part of backup/restore.

Controller roots, ONVIF catalogs/credentials and Port face guards are immutable
private objects published/read back before selecting their references. Old
objects/history are retained for Undo/recovery, not silently deleted. Private
secret values never appear in confirmation HTML, JSON status, query strings,
audit records or browser storage. Do not expose private operational metadata as
public diagnostics.

## Host-declared model and decoder choices

The browser never chooses an arbitrary filesystem path, downloads a model,
copies another profile's key or loads weights. A host operator installs and
licenses the eventual runtime's models separately. Publish existing owned
regular files into a new owner-only binding file, for example:

```sh
python -m aikey.port_feature_models --kind face --name 'Installed face set' --output /private/admin/face-binding.json --detector-host /private/models/detector.onnx --detector-runtime /models/detector.onnx --embedder-host /private/models/embedder.onnx --embedder-runtime /models/embedder.onnx --embedder-input arcface
python -m aikey.port_feature_models --kind sound --name 'Installed sound set' --output /private/admin/sound-binding.json --model-host /private/models/sound.onnx --model-runtime /models/sound.onnx --class-map-host /private/models/classes.json --class-map-runtime /models/classes.json
```

The output parent must already be owned/private. Publication is create-only,
bounded to 30 seconds and 1 GiB per input, SHA-256/read-back verified; it does
not assert ONNX format, quality, license or native compatibility. Runtime paths
refer to the processor's eventual namespace, not automatically to the host.
No key/password appears in these commands. Then attach each explicitly:

```sh
local-aikey-control run --state-dir /private/admin --aiport-instance entrance=/private/port/config.json --camera-pool-decoder aiport:entrance=/usr/bin/ffmpeg --port-model-binding aiport:entrance=/private/admin/face-binding.json --port-model-binding aiport:entrance=/private/admin/sound-binding.json
```

The sample requires actual private paths and a separately initialized Admin;
it does not start a processor. Existing saved model bindings can also be reused
without manual JSON. A new capture pool needs a host-declared decoder (or the
one unambiguous existing decoder). The server validates attached profile IDs
and private catalogs at startup. Current-file publication is only a hash check,
not a durable claim that an eventual mount still contains those bytes; the
processor's existing pinned model loader remains authoritative.
